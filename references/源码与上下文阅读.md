# 源码与上下文阅读

## 适用边界

本文件规定项目上下文的读取深度、连续会话复用、场景扩展和影响分析。IDEA MCP、项目归属和证据优先级服从 `SKILL.md`。

修改前确保已经完整掌握目标文件的当前内容和足以判断行为的上下文；已有内容仍完整、未变化时直接复用，不为确认状态重复读取。

## 连续会话复用

同一对话默认复用已经完整掌握的文件内容、项目结构、符号位置、调用关系和分析结论。

仅在以下情况补充读取或重新扫描：

- 当前任务涉及此前没有读取的文件或符号；
- 所需正文不在当前有效上下文中；
- 文件已经修改，需要掌握修改后的必要内容；
- 首次读取失败、被截断或范围不完整；
- 上下文压缩后没有保留必要正文；
- 新检查或运行结果与已有结论冲突；
- 用户明确要求重新读取、扫描或审查。

补充读取前先明确证据缺口，再从最接近目标的文件、符号或调用方开始；取得足够证据后停止扩展。搜索结果、调用分析、inspection
和差异属于新证据，不属于重复读取。

## 最小阅读闭环

1. 读取目标声明、完整方法或组件上下文及配置入口。
2. 按实际行为读取直接调用方、被调用方、接口实现和输入输出类型。
3. 按影响读取持久化、SQL、序列化、权限、异常、前端调用和相关测试。
4. 查找最接近的既有实现，确认项目约定和可复用能力。
5. 证据足以解释行为、确定范围和识别影响后停止扩展。

框架或依赖 API 不明确时，用 IDEA 查看当前版本对应源码，确认空值、异常、注解、扩展点、父类行为和版本差异。

## 场景扩展

- Bug：沿报错、堆栈、输入、状态和输出还原实际路径，核对配置、数据约束、测试和相似修复。
- 后端接口：按 HTTP method 与路径追踪 Controller、请求校验、Service、持久化、响应、异常、调用方和测试。
- 前端页面：从路由、菜单、标题、组件、API、HTTP 路径或文案定位，再读取组件、类型、状态、公共能力和权限。
- 公共接口：覆盖全部实现和调用方、请求响应类型、序列化、前端、文档及测试，先查明兼容策略。
- 编译、测试或 inspection 失败：读取报错附近源码、符号、签名、类型和直接依赖。
- 新增实现：先找同领域已有实现、工具、组件、服务和约定，只复用语义匹配的能力。

## 后端与 API 影响

只对实际相关项追踪到真实实现：

- 契约：映射、参数来源、校验顺序、DTO/VO/Entity/DO、序列化、字段类型与默认值、分页排序、返回包装、错误码、调用方和兼容性。
- 业务与数据：状态、不变量、幂等、逻辑删除、审计、并发、Service 与持久化边界、SQL 和数据库约束。
- 事务与异步：事务入口、传播、回滚、异常转换、锁与重试、提交后缓存、消息、事件和任务的执行时机及失败语义。
- 权限与租户：认证、功能和数据权限、租户上下文的建立、传递、过滤、缓存隔离及异步传播。
- 缓存、异常与配置：缓存键、作用域、失效与一致性，业务异常、日志、外部返回、配置默认值和环境差异。

先查明能够由项目事实确定的内容。必要查证后仍不能唯一确定，且不同选择会改变业务行为、范围、契约、数据、权限或结果时，按
`SKILL.md` 的事实、决策与授权规则处理。

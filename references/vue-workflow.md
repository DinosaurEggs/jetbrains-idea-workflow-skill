# Vue 开发工作流

本文件只规定 Vue 页面、组件、指令、composable、store、动态 DOM 和 Vue 工具链的专项要求；通用前端契约与状态继续应用 [frontend-workflow.md](frontend-workflow.md)。

## 动态 DOM 与 Teleport 样式

处理 Vue、第三方 Vue 组件或 Teleport 动态生成的 DOM 时：

- 局部样式优先锚定模板节点上直接声明的自有静态类，状态类使用显式 `:class`。
- 能在菜单、选项、插槽或内容根节点声明类时直接声明，不让局部选择器只依赖 `popper-class` 等组件参数或第三方运行时内部类。
- 运行时生成的外层容器优先使用组件官方样式 API、CSS 变量或项目已有主题能力。
- Teleport 内容可以使用非 scoped 样式，但选择器仍须锚定模板中的显式类；不得仅为逃避检查把局部样式迁移到全局文件。
- 不得只为消除 IDEA 警告而修改 `teleported`、挂载位置、定位、触发方式、布局或业务逻辑，也不得抑制检查或删除有效样式。
- 本次新增或修改的“选择器从未使用”问题必须通过模板类与选择器关系解决，并重新执行适用的 IDEA inspection；不得直接按框架误报处理。

## 变更文件检查与类型影响

自动检查范围只包含本次任务由 agent
修改或新增的明确文件，不包含用户已有的无关改动。先读取项目现有清单、锁文件和检查配置，查明实际包管理器、工具、脚本、支持的文件类型与参数；读取定义不等于获得执行授权，不得安装依赖、猜测入口或切换工具链。

按项目配置为本次变更文件选择适用的脚本与模板语法检查、样式检查和格式检查。文件级检查必须由工具原生支持明确文件路径，实际只覆盖这些文件，全程只读且不带自动修复或写入参数；支持批量路径时一次传入适用文件，超出工具限制时分批覆盖，不遗漏文件。

涉及 Vue 单文件组件、TypeScript、类型配置、公共类型、全局声明、公共组件或 API
类型时，先分析直接和间接类型影响、相关调用方与公共契约。纯样式、静态资源或文档变更通常不产生类型影响，项目规范另有要求时以实际内容查证。

需要项目配置、跨文件依赖图或其他文件范围之外的上下文才能形成可靠结论时，只将相应操作列为候选附加验证，并按 [execution-validation.md](execution-validation.md)
判定实际作用范围和授权。不得通过工具不原生支持的单文件参数伪造可靠的文件级结论；扩大影响分析不等于扩大编辑范围。

## 检查与授权顺序

1. 先按 [edit-check-validate.md](edit-check-validate.md) 格式化本次变更文件并执行 IDEA inspection。
2. 再执行已经判定为默认授权、适用于对应文件类型的文件级只读检查；不得因存在候选附加验证而延后。
3. 汇总文件级检查和类型影响分析后，判断是否存在需要文件范围之外上下文的候选附加验证。
4. 对每个候选项查明实际入口、目标和作用范围，只在用户当前指令唯一覆盖该操作及范围，或用户明确确认后执行；否则停止该项并记录为未执行。
5. 未获授权不影响已经完成的文件级检查结果。只有用户或项目 `AGENTS.md` 将候选附加验证明确列为完成条件时，未执行才阻塞交付；其他情况带验证边界交付，不得表述为通过。

检查发现问题后是否修改代码，按 [execution-validation.md](execution-validation.md) 区分纯验证任务与已授权修复任务；修复后重新格式化并复查受影响文件。

需要通过终端运行项目现有文件级检查时，项目语义和检查范围应先使用 IDEA MCP 确认，且所选方式须符合项目现有工具链；CodeGraph
可用于辅助定位上下文。

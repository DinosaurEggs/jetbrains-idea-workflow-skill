# 执行与验证

本文件统一规定格式化、inspection、lint、类型检查、构建、测试、运行、浏览器、截图和长任务的授权、执行边界与结果判定。

## IDEA MCP 门禁

需要项目源码、inspection、运行配置、构建或执行能力时，先应用 [idea-mcp-gate.md](idea-mcp-gate.md)。IDEA MCP 未连接、插件异常、当前项目不匹配或必需能力不可用时，按该门禁暂停；不得改用终端、普通文件系统、其他 MCP、其他 IDE 或替代实现继续依赖该能力的工作。

## 授权判定

每次启动格式化、检查、构建、测试、服务、浏览器、调试、运行配置、脚本或包装入口前，依次完成：

1. 读取项目已有定义，查明入口展开后的实际行为、参数、配置、目标对象、作用范围和副作用；不按名称、耗时、是否只读或是否属于静态分析分类。
2. 只有限定到本次任务修改或新增明确文件的相关格式化，或者工具原生支持且实际传入这些文件路径、结果只覆盖这些文件、全程只读且不包含自动修复或其他写入行为的检查，才判定为文件级默认授权。
3. 实际目标包含目录、模块、项目或工作区，依赖隐式默认范围、项目配置或跨文件依赖图，产生文件检查之外的外部状态或持续运行环境，或者仍无法证明满足上一步时，均判定为非默认授权。
4.
非默认授权操作只有在用户当前指令唯一覆盖同一操作及其实际目标和范围，或用户看过拟执行入口、目标范围、预计影响和必要副作用后明确确认时才能启动。范围不清时先查明；仍不能唯一确定时按 [core-workflow.md](core-workflow.md)
请求确认。

修改任务默认授权且必须完成的常规闭环仅包括：

- 对本次任务修改或新增的明确文件执行 IDEA 格式化和 inspection。
- 对这些文件执行项目已有、适用于对应文件类型的文件级只读语法、风格和格式检查。
- 查看已有运行配置、脚本定义、项目配置和既有结果，但不启动任务或改变外部状态。

技术上适用、项目规范建议、入口已经存在、操作只读或增量，以及任务要求实现、修复、检查、确保结果或完成验证，都只能说明候选操作的价值，不能替代授权。修改范围授权也不自动包含非文件级验证授权；沉默、推荐项和未回复不构成授权或跳过。

脚本、运行配置、IDEA 子工具和其他包装入口均按展开后的实际行为与作用范围判定；统一入口或间接调用不降低授权等级。不得通过宽泛目录、项目配置、工作区、隐式默认范围，或工具并不原生支持的文件参数，把非文件级操作表述为文件级检查。

用户明确选择跳过后记录未执行项，不表述为通过。用户当前指令已经唯一覆盖实际操作及范围时直接执行，不重复确认；授权只覆盖已说明的目标、配置、参数和合理必要的最小前置步骤，不扩展到其他操作、持久化环境修改或独立长任务。

## 最小验证

获得授权后优先选择能验证本次变更的最小范围：目标 inspection、目标测试或入口、已有最小运行配置、文件或模块级构建，最后才是全量构建或全量测试。保留既有配置默认值；只有运行配置明确支持动态覆盖且授权范围需要时，才传入临时参数、工作目录或环境变量，不持久化修改配置。

超时、缺少退出码、未分析、输出截断、问题列表或批次不完整均不能表述为通过。进程可能仍在运行时只报告已启动或结果未完成，并复用原会话继续读取结果。

## 验证失败后的行为

- 用户只要求分析、运行或验证时，失败后读取足以说明原因的输出和相关源码，只报告失败、影响与可执行下一步；不得自动修改代码或进入修复循环。
- 用户已明确要求修复或当前任务本身包含实现与修复时，只修复本次变更新增或直接相关的问题，并执行“修复、格式化、inspection、原范围验证”闭环。
- 同一问题连续修复验证最多三轮；三轮后仍失败，停止修改并报告当前证据、已尝试内容和剩余阻塞。环境、权限、端口、索引、配置或依赖问题不计为代码修复轮次，也不得通过改业务代码绕过。

## 命令与运行依赖缺失

命令不存在，或必需模块、包、插件、运行库、驱动和兼容版本缺失时，停止依赖该项的执行，并保留原命令、用途、项目声明和关键错误依据。只允许从项目已有清单、锁文件、脚本、运行配置和当前错误中确认预期入口。

未经明确授权不得安装、升级、降级、下载或卸载组件，不得修改 `PATH`、解释器、运行时、虚拟环境、IDE 配置、项目依赖或锁文件，也不得猜测命令别名、尝试其他版本、切换包管理器或改用未声明的工具绕过。说明缺失项与影响后，请用户选择处理、批准明确命令或跳过相关验证。

命令已经正常启动但返回代码、参数、输入或业务错误时，按验证失败规则处理，不归类为依赖缺失。

## 高输出与结果复用

执行可能产生大量输出的任务前，优先选择原生命令的精简输出、结构化报告或输出文件。工具返回会话 ID、任务 ID 或完整输出路径时，后续等待和读取同一结果，不重新启动任务。

仍可能超出输出上限时，首次执行就把 stdout、stderr 和退出码保存到系统临时目录的唯一日志，不写入项目。后续通过读取尾部、分段或搜索已有日志分析，不得仅为筛选、统计、查看末尾或取得未截断预览而重跑。

只有代码、配置或输入已改变，原任务实际未启动，明确的临时故障处于允许重试范围，必需状态已由用户处理，或用户明确批准不可恢复结果的重跑时，才能再次执行。日志和交付内容不得泄露密码、令牌、连接凭据或其他敏感信息。

# 系统功能详细设计格式

## 使用边界

只在 `SKILL.md` 已经判定需要系统功能详细设计，或者用户明确要求该正文时使用本文件。本文件用于确定目标系统应该具有的业务规则、主流程、关键分支、状态转换、使用主体、角色权限、输入、输出、异常和用户反馈。

仅因尚未读取源码、配置、文档或数据库，不构成本文件的适用条件；先完成必要查证。目标系统行为和验收边界已经确定，当前任务只需说明代码、页面、接口、数据、可执行配置或测试如何实现时，使用
`工程开发计划格式.md`。

开始正文前，解决所有会改变系统行为、权限、输入输出、状态、界面、数据或结果的事实和选择。

## 正文结构

正文依次包含：

1. 系统概述。
2. 系统设计。
3. 数据库设计，仅在实际涉及数据库设计时使用。

系统设计按项目真实功能结构组织。角色、客户端、管理端或其他维度本身构成系统信息架构时，可以作为分组；不得为了符合固定格式改变项目实际结构。

父级功能存在适用于全部子功能的共同规则时，在父级说明一次；最末级功能说明其特有行为，不复制父级规则。

## 系统概述

说明设计范围、触发与前置条件、主流程、关键分支和结束结果。

流程包含多个依赖步骤、分支或状态转换时，提供逐步说明和流程图。用户指定图示格式时按其要求；未指定时使用当前输出环境能够正确呈现的
Mermaid 或 ASCII。

只使用项目证据或用户已经确认的业务事实。

## 系统设计

每个实际功能说明：

- 功能描述：目标、使用主体、权限、前置条件、输入、输出和边界；
- 界面：存在界面时说明入口、区域、字段、按钮、状态和反馈；布局关系无法通过文字唯一表达时提供简图；
- 处理：存在处理规则时，按操作、状态或步骤说明触发、校验、权限、核心处理、数据变化、外部调用、返回和异常。

接口契约、配置变化和必要伪代码放入对应处理项，不另建与功能无关的自由章节。

## 数据库设计

实际涉及数据库设计时，说明现有结构、受影响表、字段、关系、索引、约束、迁移和恢复方案。需要提供或执行 SQL 时遵守 `数据库SQL与持久化层.md`
；提供 SQL 不代表获准执行。

## 完整性要求

- “系统概述、系统设计、数据库设计”的顺序保持一致，数据库设计不适用时省略。
- 使用主体、权限、字段、按钮、状态转换、处理规则、异常和数据设计必须能够追溯到项目证据或用户已确认事实。
- 可选内容是否适用，先通过项目事实查明；必要查证后仍无法确定且会改变正文结果时，再按 `SKILL.md` 处理待定决策。
- 区分现状事实和拟议变更，核对前后端字段、状态、权限、异常、数据库和配置的一致性。
- 不保留推荐、暂定、占位或留到实施阶段决定的设计内容。
- 不复制示例文档中的业务实体、角色、功能、界面或数据库内容。
- 正文只确定系统行为和必要的系统级契约，不列出逐文件、逐符号的代码修改清单或具体检查命令；这些内容属于工程开发计划。

# 命令执行可靠性

本文件统一规定命令构造、PowerShell 与路径处理、验证证据表达及失败恢复。是否允许执行仍按
[execution-validation.md](execution-validation.md)、[database-sql.md](database-sql.md) 和
[high-risk-confirmation.md](high-risk-confirmation.md) 判定；本文件不产生额外授权。IDEA 子工具名称和参数只以
[idea-mcp-execute-tool.md](idea-mcp-execute-tool.md) 的当前契约为准。

## 执行前核对

执行 IDEA 子工具命令、终端命令、脚本、运行配置、格式化、检查、构建、测试或 SQL 前，逐项核对：

1. 明确命令目的、实际入口和预期取得的证据，不按命令名称猜测行为。
2. 从当前项目定义或当前工具契约取得精确工具名、参数名、必填项、类型、条件组合和作用范围，不使用记忆中的旧名称，不试探别名。
3. 确认所用 Shell、工作目录、目标项目或模块、路径基准和目标对象；相对路径必须能从当前工作目录唯一解析。
4. 检查字符串、引号、数组、对象、布尔值、数字、空字符串、转义、参数边界和互斥组合。
5. 查明输出位置、退出状态和完整性信号，预先确定什么结果只能表示已启动、失败、不完整或通过。

项目脚本、运行配置、包管理器别名和包装入口必须先读取其当前定义，再按展开后的命令和范围执行。IDEA 子工具命令还必须逐项核对
[idea-mcp-execute-tool.md](idea-mcp-execute-tool.md) 中对应工具行；参数错误只能依据该行或错误结果明确指出的内容修正。

## PowerShell、路径与编码

- 区分 PowerShell 命令、原生可执行文件、`.cmd` 和 `.bat` 入口，按实际入口处理参数，不把其他 Shell 的写法直接套用到
  PowerShell。
- 含空格、特殊字符或可能被 PowerShell 重新解释的参数必须保持为目标程序需要的单个参数。引号和 `--%` 只在当前入口确有需要时使用，不作为
  Maven 或其他工具的固定模板。
- 模块命令先从项目结构和构建定义查明模块及上游依赖，不根据一次历史成功命令自动添加或删除聚合参数。
- 多个候选路径中存在可选或可能不存在的路径时分别探测；不要让一个不存在的路径使其他有效目标的结果被整体误判。
- 优先使用精确路径和精确目标，避免不必要的宽泛搜索、通配符或隐式默认工作目录。
- 执行本 skill 的 Python 脚本时显式使用 `python -X utf8`。读取外部日志时根据其 BOM、工具声明或实际编码处理，不默认所有输出都是
  UTF-8。
- 非零退出码的含义按具体命令判断；聚合命令包含多个检查时，分别分析各部分结果，不只依据最外层退出码下结论。

## 验证证据

记录和交付验证结果时必须同时说明：

- 范围：文件、目录、模块、项目或运行环境。
- 阶段：格式化、静态检查、编译、测试、启动、浏览器或外部联调。
- 完整性：完整、不完整、超时、截断、取消或缺少退出状态。
- 时效性：结果是否在当前代码、配置和输入之后取得。

不得跨范围或跨阶段扩大结论：文件级检查不等于模块或项目通过，静态检查不等于编译或运行通过，测试通过不等于服务、浏览器或外部链路通过。修改前的旧结果、部分批次、工具外层调用成功、补丁
applied、`errors: []`
或单独的零退出码，都不能脱离实际覆盖范围作为完整通过证据。

`timedOut`、`more`、`notAnalyzedReason`、截断、取消、缺少退出状态或结果丢失均表示未完成。只报告已经取得的证据，未执行或未完成的阶段明确标为未验证或结果不完整。

## 失败恢复

失败后先保留原命令、Shell、工作目录、输入、配置、输出和错误，再按原因处理：

| 失败类型                         | 恢复方式                                                                                                       |
|----------------------------------|----------------------------------------------------------------------------------------------------------------|
| 工具或参数错误                   | 重新核对当前契约，只修正契约或错误结果明确指出的内容；不得依次试探拼写、别名或清单外工具。                     |
| 路径或工作目录错误               | 只读确认精确路径、归属和路径基准，条件改变后再执行。                                                           |
| 确定性代码、配置、输入或测试失败 | 分析失败原因；输入和状态未变化时不重复运行同一命令。当前任务已授权修复时，修复后只复跑原验证范围。             |
| 环境或依赖缺失                   | 停止依赖该项的执行并报告缺失内容；不得自行安装、切换工具链或修改业务代码绕过。                                 |
| 瞬时连接或传输故障               | 只有操作可安全重试且不会重复副作用时，允许一次最小范围重试。                                                   |
| 批次不完整或结果丢失             | 只补做缺失文件、缺失批次或缺失检查，不重跑已经完整且仍有效的结果。                                             |
| 超时或进程状态未知               | 按 [execution-validation.md](execution-validation.md) 复用原会话、任务、PID 或日志确认状态，不直接启动新任务。 |
| 用户取消                         | 立即停止，将结果标记为未完成，不自动恢复。                                                                     |

同一命令、Shell、工作目录、输入、配置和相关外部状态均未变化时，不得仅为取得不同结果而重复执行。允许重试时只执行能够补齐当前证据缺口的最小操作，并保留前次失败事实。

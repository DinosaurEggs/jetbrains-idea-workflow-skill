# 高风险确认

## 适用边界

本文件处理数据库写入之外需要独立授权的高风险操作。普通数据库写入由 `数据库SQL与持久化层.md` 独立确认。

业务规则、目标或范围尚未确定时，先按 `SKILL.md` 处理待定决策；确认状态统一服从 `SKILL.md`。

## 风险判断

从以下方面判断操作是否需要独立确认：

- 是否改变版本库远端、部署环境、IDE、用户或系统配置；
- 是否会丢失数据、历史、配置或其他无法通过当前工作区普通编辑可靠恢复的结果；
- 是否超出用户明确指定的文件、模块、环境或影响对象；
- 是否改变认证、授权、租户、支付、风控、隐私、事务边界、公共 API、序列化结构或向后兼容行为；
- 是否影响其他用户、生产流量、正在运行的任务或外部系统。

普通文件编辑和文件级检查的授权由 `编辑格式化与文件级检查.md` 负责；非文件级执行由 `非文件级执行与验证.md`
负责。本文件不重复规定其默认授权。

## 必须独立确认

执行下列操作前，必须展示精确对象、范围、主要影响和恢复信息并取得独立确认：

- 删除数据库之外的文件、版本历史或其他难以恢复的内容；
- 取消非本 agent 发起的查询或任务；
- 新增、升级、降级或移除项目依赖；
- 安装、升级、降级或卸载外部工具、运行时、插件、驱动或环境组件；
- 修改 `PATH`、解释器、虚拟环境、IDE 数据源、运行配置或其他持久化项目、用户或系统环境；
- 部署、发布、Git commit、Git push、执行 CI/CD、生产脚本或具有外部副作用的批处理；
- 其他会改变外部状态，且无法通过当前工作区普通编辑可靠恢复，或影响范围超出用户明确目标的操作。

## 请求授权

确认前列出：

1. 操作及精确目标；
2. 执行范围和主要副作用；
3. 预计影响；
4. 可用恢复方式；没有可行恢复方式时，明确说明不可恢复。

信息不足时先做最小只读查证。存在会改变结果的待定事项时，暂停依赖该事项的操作，不用模糊确认补全事实。

对每个可独立批准的操作使用稳定编号和明确选项。只执行用户明确批准的对象和范围，不合并部分批准，不把推荐、沉默或泛化回复当作授权。

授权只覆盖确认时的目标、路径、版本、环境、范围和副作用。任一内容发生实质变化时重新确认；未完成确认前，只能继续不依赖该操作的工作。

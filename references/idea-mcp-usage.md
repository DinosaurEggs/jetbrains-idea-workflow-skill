# IDEA MCP 与 CodeGraph 使用约定

## IDEA MCP

涉及项目源码、符号、依赖、VCS、编辑、inspection、运行配置、构建、数据库或调试能力时，必须使用 IDEA MCP。IDEA 子工具均通过
`mcp__idea__execute_tool` 调用，统一入口的外层参数使用任务对应项目的绝对 `projectPath`，具体子工具和参数只按
[idea-mcp-execute-tool.md](idea-mcp-execute-tool.md) 的契约构造。

项目根、模块、仓库和目标文件归属按任务需要确认；修改前读取相关仓库的已暂存、未暂存、未跟踪及冲突状态。Java/Kotlin
优先使用语义符号、源码和调用分析；Vue/TypeScript、模板和配置先用精确标识或文本定位，再读取当前源码。前后端契约以 HTTP method
和 URL 串联 Controller、类型、API 封装和页面；搜索结果只提供候选，结论以 IDEA MCP 读取的当前项目内容确认。

调用结果必须客观判读：路由调用成功不等于子工具成功，warning 不等于检查通过；`errorMessage`、`timedOut`、非零退出码、
`more`、`notAnalyzedReason`、截断、缺少退出状态或部分批次都要在结果中如实记录，不能宣称未完成结果已通过。

IDEA MCP 或其子工具不可用时，不伪造已读取或已验证的证据；只报告缺失能力和影响。与项目语义无关的普通文件或文档工作可以继续，
依赖缺失证据的结论必须明确验证边界。

编辑、inspection、执行、数据库和高风险操作继续遵守各自 reference。

## 参数契约

通过统一入口构造子工具命令时，只使用 [idea-mcp-execute-tool.md](idea-mcp-execute-tool.md) 列出的工具、精确参数名和合法组合。
`projectPath` 属于统一入口外层参数，不写入子工具 `command`；子工具参数也不提升到外层。参数名区分大小写和下划线，不做
camelCase、snake_case、缩写或单复数形式的推断转换。

参数错误仅按下列契约修正：

- 缺少参数：补充契约或错误结果明确列出的必填项。
- 未知参数：删除该项，或改为契约或错误结果明确给出的名称。
- 类型或格式错误：按契约修正值、JSON 数组、JSON 对象、布尔值、数字、空字符串或转义，不试改参数名。
- 条件组合错误：选择契约规定的一种完整模式，删除与该模式互斥的参数。

修正前重新核对对应工具契约；不得依次试探多种拼写、改用清单外工具或把同一错误无依据地反复提交。连接、传输、会话或插件问题应如实记录，不把参数修正规则用于掩盖能力故障。

## 项目与能力边界

用 IDEA MCP 确认项目根、模块、仓库和目标文件归属。修改前读取相关仓库的已暂存、未暂存、未跟踪及冲突状态；对应子工具存在时可优先使用项目/VCS
能力。

- 目标文件有既存改动时以当前内容为基础最小编辑，不恢复基线；冲突使任务无法可靠继续时保留现场并询问。
- 通过统一入口选择满足目标的最窄子工具能力。Java/Kotlin 优先语义符号、源码和调用分析；Vue/TypeScript、模板和配置先用精确标识或文本定位，再读当前源码。
- 前后端契约以 HTTP method 和 URL 串联 Controller、类型、API 封装和页面；搜索只提供候选，结论以当前源码确认。
- 依赖、JDK、JAR/JRT 或反编译源码由 IDEA 直接读取；符号重命名使用语义重构，不做文本全局替换。

编辑、inspection、执行、数据库和高风险操作遵守各自 reference，本文件不重复其规则。

## CodeGraph

项目上下文读取必须使用 CodeGraph 辅助定位文件、符号、调用关系和影响候选。先服从项目 `AGENTS.md` 的优先级、触发条件和查询方式，
再服从工具实际契约；查询不得使用自然语言。CodeGraph 结果仅用于确定候选，关键声明、配置及测试结论由 IDEA MCP 当前项目复核。

与 IDEA MCP 结果冲突时以 IDEA MCP 为准；已有结果足够时复用，不为展示方式重复查询。CodeGraph 不可用或无结果时停止继续尝试，
不自行初始化或修复索引，并使用 IDEA MCP 完成可取得的上下文读取。

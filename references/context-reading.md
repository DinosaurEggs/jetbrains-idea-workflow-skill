# 源码与上下文阅读

## 证据边界

首次访问项目前应用 [idea-mcp-gate.md](idea-mcp-gate.md)。搜索、符号、调用树和 CodeGraph 只用于确定候选；结论来自 IDEA 当前项目中相关源码、配置、依赖及任务需要的数据库只读信息。

修改前必须阅读目标文件当前内容和足以判断行为的上下文，不凭文件名、片段、错误文本或印象修改，也不为“完整了解”遍历无关项目内容。

## 连续会话复用

同一对话中的后续任务默认复用当前上下文已经完整掌握的文件内容、项目结构、符号位置、调用关系和分析结论。对于读取后未修改、且所需内容仍保留在当前上下文中的文件，不得仅为确认状态而重复读取，也不得换用其他命令或工具读取相同内容。

已有项目认知足以支持当前任务时，不得重复执行目录遍历、全局搜索、架构探索或调用链扫描。后续任务直接从当前目标开始，不先做预防性项目探索。

仅在以下情况补充读取或重新扫描：

- 当前任务涉及此前没有读取过的文件或符号；
- 所需的具体代码不在当前有效上下文中；
- 文件在上一个任务中被修改，需要读取修改后的必要局部；
- 首次读取失败、被截断或范围不完整；
- 上下文压缩后没有保留必要正文；
- 检查或运行结果与已有结论发生冲突；
- 用户明确要求重新读取、重新扫描或重新审查。

需要补充时，先明确缺少的具体证据，再从最接近目标的文件、符号或调用方开始，只读取能够补齐缺口的最小范围；取得足够证据后停止扩展。搜索结果、调用分析、inspection
和差异等新证据不属于重复读取。

## 最小闭环

从目标符号和直接行为链开始，按实际依赖扩展：

1. 读目标声明、完整方法或组件上下文及配置入口。
2. 读直接调用方、被调用方、接口实现和输入输出类型。
3. 按影响读持久化、SQL、序列化、权限、异常、前端调用和相关测试。
4. 查找最接近的既有实现，确认项目约定和可复用能力。
5. 证据足以解释行为、确定范围和识别影响后停止扩展。

框架或依赖 API 不明确时，用 IDEA 查看对应源码，确认空值、异常、注解、扩展点、父类行为和版本差异。

## 场景路由

- Bug：沿报错、堆栈、输入、状态和输出还原实际路径，核对配置、数据约束、测试和相似修复，不从错误文本猜原因。
- 后端接口：按 HTTP method 与路径追踪 Controller、请求校验、Service、持久化、响应、异常、调用方和测试。
- 前端页面：从路由、菜单、标题、组件、API、HTTP 路径或文案定位，再读组件、类型、状态、公共能力和权限。
- 公共接口：覆盖全部实现和调用方、请求响应类型、序列化、前端、文档及测试，先查明兼容策略。
- 编译、测试或 inspection 失败：读报错附近源码、符号、签名、类型和直接依赖；后续遵守编辑与执行规则。
- 新增实现：先找同领域已有实现、工具、组件、服务和约定，只复用语义匹配的能力。

## 后端与 API 影响

只对相关项追踪到真实实现：

- 契约：映射、参数来源、校验顺序、DTO/VO/Entity/DO、序列化、字段类型与默认值、分页排序、返回包装、错误码、调用方和兼容性。
- 业务与数据：状态、不变量、幂等、逻辑删除、审计、并发、Service 与持久化边界、SQL 和数据库约束；仅在结论依赖实时状态时查库。
- 事务与异步：事务入口、传播、回滚、异常转换、锁与重试、提交后缓存、消息、事件、任务的时机及失败语义。
- 权限与租户：认证、功能和数据权限、租户上下文的建立、传递、过滤、缓存隔离及异步传播，不自行扩大绕过范围。
- 缓存、异常与配置：缓存键、作用域、失效与一致性，业务异常、日志、外部返回、配置默认值、环境差异及对前端、测试和监控的影响。

## 查证与决策

先查明能够由项目事实确定的内容。仍不能唯一确定且会改变业务行为、范围、契约、数据、权限或结果时，只做问清问题所需的最小只读查证，再按 [core-workflow.md](core-workflow.md) 暂停依赖该事项的工作。

阅读完成后判断是否需要设计、数据库查证或高风险确认，以及对公共接口、数据库、事务、权限、租户、缓存、异步、日志、异常、兼容性、测试和配置的实际影响。

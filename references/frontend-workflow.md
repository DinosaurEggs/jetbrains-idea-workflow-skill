# 前端开发工作流

本文件规定所有前端任务共用的上下文、契约、状态、联调、响应式和可访问性要求。Vue 专项规则、视觉质量细则和执行验证分别由对应 reference 负责。

## 规则路由

- 涉及 Vue 页面、组件、指令、composable、store 或 Vue 工具链时，追加应用 [vue-workflow.md](vue-workflow.md)。
- 新建页面或组件、视觉重构、样式美化、品牌体验或用户明确要求提升设计质量时，追加应用 [frontend-design-quality.md](frontend-design-quality.md)。
- 格式化、inspection、lint、类型检查、构建、测试、启动、浏览器或截图操作统一应用 [execution-validation.md](execution-validation.md)。
- 涉及项目语义时使用 IDEA MCP，并使用 CodeGraph 辅助读取和定位上下文；CodeGraph 结果由 IDEA MCP 复核。

## 定位与上下文

根据任务搜索路由、菜单、页面标题、组件、API 方法、HTTP method 与 URL、store、状态逻辑、权限标识和用户可见文案。修改前按实际影响阅读：

- 页面、表单、弹窗、详情及相关公共组件。
- API 封装、请求与响应类型、状态管理和复用逻辑。
- 路由、菜单、权限配置和设计系统入口。
- 对应后端 Controller、DTO/VO、返回结构及异常契约。
- 相关测试和项目中已有的同类实现。

搜索或符号结果只用于定位；结论和编辑必须基于当前源码、配置与接口契约。

## 契约与行为

修改前查明并核对：

- 查询、表格、表单和详情字段的名称、类型、必填、默认值、枚举、字典及日期时间格式。
- 请求参数、响应结构、分页、排序、错误码、异常提示和后端校验是否一致。
- 菜单、页面、按钮和数据权限是否一致，受限状态是否真实阻止未授权操作。
- loading、empty、error、disabled、readonly、hover、focus、selected 和权限受限状态中，哪些适用于当前组件，以及状态之间能否正确切换和恢复。
- 修改是否影响公共组件、其他页面、缓存状态、路由生命周期或并发请求。

完成必要查证后仍无法唯一确定且会改变业务行为、接口契约、权限或结果的事项，按 [core-workflow.md](core-workflow.md) 的待确认事项规则暂停依赖它的工作。

## 前后端联调

以 HTTP method 和 URL 为连接点，同步核对前端请求、API 类型、后端参数与 DTO/VO、响应字段、字典或枚举、日期时间格式、错误响应和用户提示。不得只修改一端后假设另一端兼容；存在兼容性要求时查明所有相关调用方。

## 响应式与可访问性基础

- 在项目或用户要求支持的目标视口中保证文本、控件、浮层、表格和动态内容不溢出、不遮挡，状态变化不造成无意义的布局跳动。
- 使用明确的 grid、flex、断点、`aspect-ratio` 或 `min/max` 约束稳定固定格式控件、工具栏、网格、看板和计数区域。
- 保证核心流程可通过项目支持的鼠标、键盘或触控方式完成；焦点可见、顺序可预测，语义标签、可访问名称和错误反馈完整。
- 必要信息不得只依赖颜色、悬停或动画表达，并保持文本、图标、边框、状态和焦点的可辨识对比度。

领域风格、排版、色彩、布局密度、控件选择、动效、素材和更高阶可访问性要求只在 [frontend-design-quality.md](frontend-design-quality.md) 中规定。

## 修改边界

- 优先复用项目已有组件、类型、设计系统和交互模式，不把局部任务扩大为公共改造或全站重设计。
- 只修改任务需要的文件，不覆盖或顺带格式化用户已有的无关改动。
- 修改完成后按 [edit-check-validate.md](edit-check-validate.md) 检查本次变更，并按 [execution-validation.md](execution-validation.md) 处理授权、结果完整性和失败后的行为。

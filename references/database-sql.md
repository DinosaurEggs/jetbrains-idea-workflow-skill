# 数据库、SQL 与持久化层

## 选择证据

先按任务范围阅读相关源码、迁移文件、配置和项目文档。修改显式 SQL、ORM 查询、查询构造、Repository/DAO/Mapper 或字段映射时，按需核对持久化层接口、Entity/DO、DTO/VO、映射配置、分页排序、逻辑删除、租户、数据权限、测试及相似实现。

只有结论依赖数据库当前状态时才强制使用既有 IDEA 数据源只读查库，例如：

- 当前 schema、字段类型、约束、索引或数据库对象可能与源码或迁移记录不一致。
- 字典、状态、配置或少量实际数据决定业务结论。
- 正在定位数据不一致、查询结果异常、执行计划或数据库环境特有问题。
- 即将设计依赖现有结构的数据库变更，且项目事实不足以可靠确定当前基线。

源码、迁移文件和明确契约足以支持结论时，不为形式完整强制连接实时数据库；若实时状态仍可能影响结果，在交付中说明未核对范围。完成必要查证后仍无法唯一确定业务口径、字段语义、关联条件或数据边界时，按 [core-workflow.md](core-workflow.md) 处理待定事项。

## 有限只读查询

查看既有连接、schema、表结构、约束、索引和执行计划，以及执行有限条件的 `SELECT`、`SHOW`、`DESCRIBE` 或等价只读语句，通常免确认，但必须：

- 选定任务所需的数据源、数据库和 schema，限制字段、条件与行数，不做无目的全表读取或完整导出。
- 避免读取敏感字段，不在工具输出或最终回复中泄露凭据、个人信息及无关数据。
- 仅按任务需要翻页读取结果；返回错误信息时视为失败，不根据结果集标识或部分文本推断成功。
- 只取消本 agent 发起且仍在运行的查询；取消其他查询或编辑数据源按 [high-risk-confirmation.md](high-risk-confirmation.md) 处理。

测试既有连接和按需加载必要元数据属于查证。创建、编辑或替换数据源及其持久化配置必须独立确认；DDL data source 只能用于读取脚本结构，不能冒充实时连接执行查询或数据预览。

## SQL 与映射检查

查询或映射变更应核对：

- 字段类型、长度、NULL 与默认值，别名及映射目标是否一致。
- `WHERE` 是否包含适用的逻辑删除、租户、权限和状态条件，时间与范围边界是否正确。
- `JOIN` 和聚合是否放大行数或重复计数，分页层级与稳定排序是否正确。
- 查询是否使用合适索引；必要时执行有限只读 `EXPLAIN`，不得据此自行创建或修改索引。

根据项目实际使用的持久化方案，追加核对动态 SQL、参数绑定、结果映射、实体关系、抓取策略、级联行为、生成 SQL 或响应式事务等相关机制；不得默认项目使用 MyBatis。

## DDL/DML 提供与执行

DDL、DML、索引和任何可能改变数据或结构的存储过程默认只提供，不直接执行。提供时写明用途，并尽量包含前置条件、预期影响和适用的回滚或恢复方案。

只有用户已经看到并明确确认以下全部信息后，才可执行：

1. 待执行的精确 SQL 或等价操作内容。
2. 目标数据源、数据库及适用 schema。
3. 影响范围，包括筛选条件、对象、预计数据范围或结构变化。

用户最初提出“改库”“执行 SQL”等请求，不代表对尚未展示的语句、目标和范围预先授权。确认时为每个可独立执行的语句或批次使用稳定编号，并提供“执行”“仅提供、不执行”“修改后重新确认”等明确选项；通用确认状态按 [core-workflow.md](core-workflow.md) 处理。

授权只覆盖确认时展示的 SQL、目标和范围。任一内容发生实质变化，或多条语句中只有部分获批时，只执行仍被精确覆盖的部分，其余重新确认。提供 SQL、把 SQL 写入项目文件或生成迁移脚本，均不等于获准对数据库执行。
